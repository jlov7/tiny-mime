# Tiny Mime v02 exact API and record contracts

This supplement is normative with chapter 02. The JSON schema supplies closed named structures under `$defs`; validate an endpoint against its matching definition, not against the root PublicRound schema. JSON Schema validates structure; ownership, state transitions, Unicode normalization, references and retention are mandatory semantic checks. No app implementation is included here.

## Shared rules and responses

- API origin is http://127.0.0.1:4317. Host must match. Every mutation requires exact Origin and Content-Type application/json (optionally charset=utf-8); reject unexpected encoding/content type. Reject duplicate keys, prototype keys, invalid UTF-8 and unknown properties. POST bodies max 4,096 bytes except events 16,384 and operator score import 70,000. Downloads have separately bounded sizes below.
- Session owners and operator capabilities are different RAM-only random identities. Require cookie before returning resource-specific errors; no ID alone grants access. GETs need cookie/Host and reject Sec-Fetch-Site=cross-site when supplied. They need not have an Origin header; if one is present it must match. No CORS/JSONP or top-level secret-bearing GET mutations. Mutations always require Origin even if fetch metadata is absent.
- requestId is lowercase UUIDv4, session-wide idempotency bound to method+path+normalized payload. Same ID/different digest 409; accepted duplicate returns current operation result without rerunning effects. Error body is ApiError. Limits apply after valid-duplicate lookup. Revisions increment only accepted round commands and server terminal generation changes, not read/events/feedback.
- Code→status: INVALID_INPUT400, UNAUTHENTICATED401, FORBIDDEN403, NOT_FOUND404, STALE/IDEMPOTENCY_CONFLICT/ACTIVE_ROUND409, EXPIRED410, LIMITED429, UNAVAILABLE503, DEADLINE504. No content in diagnostic errors. Round state failures are snapshots on normal reads, not transport errors.
- Session creation has no requestId because it is idempotent by existing session cookie and creates no round/call. Bootstrap/lock similarly have no resource-creation retry; uncertain bootstrap is resolved by GET operator status, never blindly resubmitted.
- Ordinary return shapes below are closed exact objects. Each primitive `id` is UUIDv4; dates ISO8601 UTC; sha256 lowercase hex 64. Nullable means explicit null, not absent. All arrays enforce max sizes. Error envelopes do not include unrelated snapshots except STALE, which requires a separate authorized read.

## Round creation and mode selection

POST /api/session {} →200 `{sessionReady:true,activeRoundId:id|null}`.

POST /api/rounds CreateRound →201 PublicRound first time,200 existing snapshot duplicate. CreateRound is `{requestId,mode,executionMode,studySessionId}` with mode private_play|study and executionMode fixture|live. Private play requires studySessionId=null; study requires owned eligible session whose executionMode matches. One active round limit across modes. Operator creator round uses a separate endpoint but the same owner/active-round rule.

PublicRound includes required executionMode fixture|live. Fixture rounds always show a persistent “Fixture rehearsal” badge; any second act from the scripted mock adapter has source=mock_fixture. They cannot enter real research tables or live exports. An enabled provider never silently turns a fixture round into live generation. A disabled provider rejects requested live creation with UNAVAILABLE before a round is created. First acts are source=authored_fixture and carry authorship; they never require a live call. Authorship is `{authoringMethod:spec_transcribed|agent_assisted|human_authored,humanReview:not_run|reviewed}`. Source runtime_generated/mock_fixture requires authorship=null. Human review never changes the recorded authoring method.

POST /api/provider-consent `{requestId,disclosureVersion,accepted:true}` →200 `{accepted:true,disclosureVersion}`. Exact disclosure version must equal enabled provider config; screen names OpenAI and explains which guess text will be transmitted and applicable provider retention. This consent is RAM/session-scoped and grants neither research storage nor publication. Live private-play creation requires it. Study has its own exact consent record. No provider-consent route accepts API keys.

Reload recovery must use the existing session cookie before any POST /api/session. A401 means lost session, not a reason to create a new owner and resend the old pending operation; discard stale metadata explicitly. Creation recovery: GET /api/round-requests/:requestId →200 PublicRound or404/410. Round recovery/read/mutation/event/feedback routes and statuses are exactly chapter 02. First-guess202 means accepted and pending, not rendered or successful generation. Every ready score is independently validated before client presentation. Failed score validation cannot enter acts. Abandoned snapshot has empty acts/guesses, null reveal and cancelled generation if there was a job.

## Study sessions, practice and optional extra

POST /api/study-sessions StudyStart →201 `{studySessionId,executionMode:'live',withdrawalCode,phase,nextRoundAvailable:true}`. The input requires owner-created studyRunId; exact consentVersion; adultConfirmed=true; participationConsent=true; rawResearchConsent=true; providerTransmissionConsent=true; retainResults30Days boolean; publicationConsent boolean. No names/contact details/signature text. Decline any required consent → no request/enrollment; private fixture play remains available. Verify study enabled, authorized budget/phase scope and approved manifest before acceptance. For a comparative schedule (including its prerequisite practice), additionally require the calibrated frozen eight-scene comparison bank. Formative and bank_calibration runs exist to obtain that evidence, so they do not require completed comparative calibration; their own approved scope, validated score drafts and consent remain mandatory. Do not claim true consent from fixture/demo/test buttons.

Withdrawal code is26 uppercase Base32 characters generated from 128 random bits (without '=' padding); return only on creation/current owned study-session read. Store an HMAC lookup key, not code in logs; show the code to participant for local withdrawal. Operator does not export it with results. POST /api/study-withdrawals `{requestId,withdrawalCode}` →200 `{deleted:true}` for matching code,404 otherwise; request uses an authenticated local session but can withdraw its matching code even if original browser session ended. Rate-limit 5 attempts/hour/session and 20/global/hour. Erase all linked research content and revocable export caches; unlink owner data. Offline copies already downloaded require operator deletion workflow and disclosure.

GET /api/study-sessions/:id →200 `{studySessionId,executionMode,phase,phaseRoundIndex,phaseRoundCount,nextRoundAvailable,optionalExtraOffered,withdrawalCode}`. Participant-owning session only. phase=formative|bank_calibration|practice|comparative|optional_extra|complete. No scene IDs, condition, schedule allocations or profiles. phaseRoundIndex is completed/initiated index specified by frozen schedule; nextRoundAvailable false while a round is active or run ended. A completed round cannot be repeated through a new requestId.

POST /api/study-sessions/:id/feedback SessionFeedback →200 `{saved:true,optionalExtraAvailable:boolean}`. Body `{requestId,wouldPlayAgain:boolean|null,optionalExtraAccepted:boolean|null}` is accepted once after planned main rounds terminate. Server first creates an optional offer only if protocol permits, a held-out safe fixture/scene exists, consent still applies and budgets permit. No answer is required. `optionalExtraAccepted=true` is valid only when offered, and enables one extra-round creation; acceptance alone does not count as started/completed. On actual extra creation record roundId only; derive started=true from the first accepted play_started event in that linked round. Creation without playback stays started=false at session close. Derive completed=true only from normal post-second-guess reveal after both clips completed and both guesses were accepted; early reveal/exit/failure is false at close, and active pending work remains null. A stale/false offer cannot invoke calls. Extra uses practice_blind_v1 and is excluded from comparative outcomes. Record offer/acceptance/started/completed distinctly.

Practice always uses profile practice_blind_v1, condition=null, randomized=false and withheld guessData even though guesses may be retained for consented human scoring. No runtime evaluator labels correctness. Comparative uses runtime_informed_v1/runtime_blind_v1 only after first guess acceptance and assigned schedule. Development probe profiles never create participant records. Add a synthetic-server fixture for all these pathways.

Study phase advancement is an atomic server transition after terminal round and optional round feedback; no participant-controlled scene or condition. GET never advances. New-round command consumes exactly the next schedule entry. Skip/abandon are terminal encounters and are not silently replaced. Completed study enters phase complete; no more calls. A second process/startup cannot resume a participant session from SQLite research data; research storage is not session authority.

## Event discriminated union

Every ClientEventV1 has exactly eventId, clientSequence (integer 0–1,000,000), elapsedMs (integer 0–86,400,000 ornull, observational elapsed from client round-load clock), name and the listed variant fields. The API schema spells all constraints.

| name | Additional fields |
|---|---|
| play_started | attempt,scoreHash,playId,playbackMode motion|frame_step,isReplay boolean |
| play_completed | attempt,scoreHash,playId,playbackMode,playedElapsedMs0–10000 |
| playback_failed | attempt,scoreHash,playId,reason validation|renderer|capture_unsupported |
| playback_mode_changed | playbackMode |
| visibility_changed | visibility visible|hidden |
| client_ready | attempt,scoreHash,submissionRequestId,submissionElapsedMs integer 0–86400000|null,recovered boolean |
| client_deadline | submissionRequestId,deadlineMs exactly 15000 |
| client_clock_uncertain | submissionRequestId,reason reload_pending|wall_clock_discontinuity |

client_ready only valid for attempt 2 tied to accepted guess1 request. play_* must reference an available validated act and owned playId; completed exact duplicated playId never increments completion count. isReplay is advisory; server derives replay count from distinct accepted play_started events. A frame_step traversal is recorded separately, never silently converted to completed full-motion playback. Timings remain untrusted observations: impossible references/ranges reject whole batch atomically, no partial acceptance. clientSequence helps diagnose ordering, but delayed/out-of-order valid events are allowed; duplicate semantics key by eventId not sequence.

Batches max 20,16KiB;120 events/minute/session,500 per round. Malformed/foreign events cannot alter counters or flags. A batch with one invalid event rejects all. Exact duplicates don't consume event-rate capacity again. At least one accepted client_ready and validated matching hash establishes client-observed readiness; provider status cannot fabricate it. Received after expiry can update only the retained 24h technical tombstone and an existing consented research record, never reopen the round. Destroy owner-tombstone link when retention expires. Do not store free-text error strings or unbounded client properties.

## Operator APIs and lifecycle

Operator-secret/capability lifecycle is recoverable without restarting the server: on lock, expiry or failed-bootstrap exhaustion, invalidate all prior launch secrets and generate a fresh one-use secret shown ONLY in terminal. Rate-limit regeneration to one/minute; local operator console command `unlock` can generate a fresh secret after that delay. The server never returns a launch secret through HTTP. Keep rounds/provider jobs intact. At most one active operator capability per process; new bootstrap invalidates old capability. Terminal absence means operator access remains unavailable until a local terminal is attached, not a browser fallback revealing secrets.

POST /api/operator/bootstrap OperatorBootstrap →200 `{operatorReady:true,expiresAt}`. GET /api/operator/status →200 `{operatorReady:true,expiresAt}` with valid capability;401 otherwise. POST /api/operator/lock {} →200 `{locked:true}`; clear cookie and regenerate terminal secret under above rule.

GET /api/operator/scenes →200 `{catalogueVersion,records:SceneMeaningV1[]}` max 12,128KiB. GET /api/operator/scenes/:sceneId/score →200 `{sceneId,scoreHash,source:'authored_fixture',authorship,score}` max 70KiB; missing draft 404. POST /api/operator/scores/validate ScoreImportInput (≤70KiB) →200 ValidationResult; only validates, does not install/overwrite catalogue. Unknown/cross-scene roster fails. Rehearsal can play returned valid data locally. Editing frozen catalogues/meanings requires a versioned source change/rebuild, not this runtime API.

POST /api/operator/creator-rounds CreatorRoundInput →201 PublicRound. Input `{requestId,sceneId,creatorOwned:true}` is explicit operator declaration that the operator will supply their own guess. It creates private_play using selected safe scene, session/provider consent requirements still apply; executionMode is included explicitly in this input too. Server tags creatorOwned=true privately. Study rounds never inherit this tag. No paid call on creation.

POST /api/operator/study-rehearsals `{requestId,fixtureScheduleId}` →201 `{studySessionId,executionMode:'fixture',phase:'practice',nextRoundAvailable:true}`. fixtureScheduleId enum `synthetic_short_v1`|`synthetic_full_v1`. Operator then enters participant mode while session ownership persists. Entire run lives in separately labeled fixture RAM/fixture-export area; no real consent, raw-research or payment records. Full synthetic schedule exercises 8 comparative targets with fake transport. TM07 may appear only in a rejection fixture, never playable content.

POST /api/operator/captures CaptureInput →201 `{captureId,filename:'tiny-mime-replay.zip',byteLength}`. Input `{requestId,roundId,includeGuessText,timing:'original'|'shortened_wait',shortenedWaitMs:number|null}`. Require owned completed revealed round, operator capability, validated completed scores and available timeline. Original requires shortenedWaitMs=null. Shortened mode requires nonnegative integer≤15000 and no longer than actual measured wait. Target is included only in the reveal segment; no hidden answer text before that segment's activation. includeGuessText=false default UI; true requires server's creatorOwned or explicit recorded publication consent for this specific research round. Refusal is403, never substitutes invented/example guesses. Pending/unavailable/abandoned rounds cannot become “successful repair” captures.

GET /api/operator/captures/:captureId →download application/zip; same operator+owner gates; no share URL. Max20MiB, expiry 10min, one successful download allowed then delete cache. Bundle: replay.html, capture-manifest.json, scores/act1.json and scores/act2.json if actually present. Self-contained HTML uses fixed authored JS/SVG engine, embedded validated data as base64 UTF-8 decoded by TextDecoder+JSON.parse and no network. Use textContent for every untrusted visible string; never innerHTML. CSP permits only the hashed fixed renderer, no remote assets/imports/fonts/connects. Test literal </script><img src=https://example.invalid/x onerror=alert(1)> with zero network calls/execution. Manifest has bundleVersion, round source/executionMode, acts hashes/authorship, actual timeline, exported timeline, timingEdited boolean, omittedGuessText boolean, consentBasis creator_owned|publication_opt_in|no_guess_text, model/prompt/engine/contact/meaning versions as permitted, createdAt and validity limitations. No credentials, study identities, raw hidden prompts or withdrawal codes. Target string is revealed only by playback state (the local owner can inspect downloaded source; this bundle is not for blinded participants). Optional WebM is separate capability-tested export, not a required output or a claim that HTML is video.

POST /api/operator/exports OperatorExportInput →201 `{exportId,filename,byteLength,expiresAt}`. Input format enums in schema. GET /api/operator/exports/:exportId →download matching CSV/JSON/ZIP; operator capability,10min expiry,max 20MiB; export audit holds only id/type/count/deadline. Coder second export needs frozen first adjudication lock; fidelity export includes one clip/hash+meaning, never guesses, condition, paired act or provider details. Operator rating import/locking is a local CLI workflow described below, not arbitrary authenticated POST upload in this version.

Local CLI `npm run study:import-ratings -- <file>` validates predeclared blinded rating JSON/CSV schema, records independent coder IDs/ratings and rejects unknown/double/conflicting rows. `npm run study:lock-first -- <studyRunId>` succeeds only after complete/explicitly missing adjudication using frozen rubric and records UTC lock. CLI reads local private files; it cannot unlock browser target access or spend provider funds. Implement schemas and tests with the export dictionary; no manual SQL edits required.

## Storage partitions and strict configuration semantics

Runtime RAM: sessions, operator capabilities, active rounds/raw guesses, request-id maps and bounded technical tombstones. Fixture research-like records go to fixture-only temporary area or RAM and exports are marked synthetic. Default private-play writes no raw content to SQLite. Consented research tables and sanitized accounting live in separate SQLite files under TM_DATA_DIR, permissions restricted to OS user. Source tree and server static directory must not contain either database. This is local access control, not encryption-at-rest or a claim of anonymity. Exact normal study/runtime prompts are not persisted; the separately authorized creator-owned probe diagnostic ledger is the explicit exception below.

ProviderConfigV1 disabled → modelId,priceSnapshot,approval null; both profiles enabled=false and all monetary caps/count 0; token caps remain the compiled 32768input/6000runtime-output/12000probe-output constants. Enabled → all required values nonnull, approval unexpired, TM_MODEL_ID exact match, at least one profile enabled and approved purpose covers it; each enabled profile must have positive call/unit/day/job caps within hard maxima; unitCap≥callCap, dayCap≥unitCap, jobCap≥unitCap; case count>0 and reserved full approved workload≤jobCap. Runtime case count bounds the activated local job/day, not unlimited authority. Unused profile all monetary caps/count 0; token caps remain the compiled 32768input/6000runtime-output/12000probe-output constants. Rate snapshots must have nonnegative prices, at least one positive, and no other charge. Currency USD only; calculate in integer microdollars, round upward. Cross-field validation rejects rather than fills missing data. Approval records are provenance of an external explicit decision, never a way for implementation to self-authorize expenditure.

Canonical score hash: RFC8785-compatible JSON canonicalization of validated score, UTF-8, SHA-256, lowercase hex. Record canonicalization version `jcs-sha256-v1`; collapse numeric−0 to0 and reject nonfinite numbers before encoding. Fixed known fields and canonical actor/key order do not replace canonical number/key serialization. Use one shared implementation plus cross-language hash vectors. Ordinary request payload digests remain server-internal and are never persisted in browser metadata.

## Frozen study manifest and rating import details

StudyRunV1 is `study-run-v1.schema.json`. It is server-only nonsecret data with studyRunId, protocol/consent/provider-disclosure versions, draft|approved status, optional bankApproval, optional-extra policy, explicit schedules and fixed retention. A draft can run only in synthetic fixture rehearsal. Approved comparative live manifest requires genuine calibration approval evidence, all eight unique comparison-scene first-score hashes and current meaning catalogue hash. Approved formative/bank-calibration manifests may have bankApproval=null; they use their separately approved phase scope and validated drafts. The gate is phase-specific. TM07 is forbidden. Changing any frozen score, meaning, prompt, model/profile, renderer/contact policy or schedule creates a new run/version and calibration review when relevant; never silently edit an active run.

Comparative schedules contain exactly two development practice entries followed by all eight comparison scene IDs once, with four informed and four blind allocations. Practice profile is practice_blind_v1/allocationnull. Comparative profile and allocation agree exactly; conceal them until first-guess acceptance assigns analysis condition. Enforce the evaluation chapter's category and scene/order balance across 24 schedules before approval. Assign each new enrollment the next least-used schedule in a server-generated shuffled tie order frozen when the run starts, without reading guesses or participant characteristics. Store only schedule ID internally. Formative/bank-calibration runs have practice_blind_v1/allocationnull and never enter comparative estimates. Optional-extra scene must not repeat one the participant already saw; if no eligible scene remains, do not offer it. A manifest is evidence of configured decisions, not by itself proof that required human approval occurred.

Rating import mandatory format is JSON matching `rating-import-v1.schema.json`; CSV import is optional and must map exactly to that JSON without inferred missingness. `version=1`, `studyRunId`, `kind=recognition_first|recognition_second|fidelity`, `role=independent|adjudication`, `coderId` matching coder_[a-z0-9]{8,32}, and rows `{rowId,rating,missingReason}`. Each rowId must come from that run/kind's specific blinded export mapping. Independent ratings require two distinct coder IDs per retained scorable row; coder IDs are pseudonyms, no names. Recognition rating is0|1|2 ornull; missingReason=null when rating present and one of no_response|deleted|unrateable when null. Fidelity rating is target_preserved|unclear|changed_story|unrateable ornull; missingReason null when rating present, no_clip|deleted when null. Frozen meaning fidelity anchors use these same exact four labels: target_preserved, unclear, changed_story and unrateable. A clip impossible to judge is unrateable rather than evidence of preservation.

Imports are atomic and bounded: ≤2,000 rows and 2MiB; unique rowIds; known run/export/kind; values satisfy missingness pair rules. Exact duplicate same coder/role/kind/row/value is a no-op; conflicting reimport is an explicit error, not overwrite. Keep independent ratings immutable. Equal independent recognition ratings can be resolved automatically to that agreed value with method=agreement; disagreements need a separate role=adjudication import from a third coder pseudonym. The same adjudication rule applies to fidelity. A deleted row cannot be re-created by import. `study:lock-first` requires each retained first-guess row resolved or an explicit permitted missingReason; lock is immutable. Once locked, second-recognition exports become available. Corrections require an explicit protocol deviation/new run artifact, never silently unlock/rewrite. CLI outputs counts/errors only, no raw guess contents.

## Offline quality-probe diagnostics

Exact prompt prohibition in normal runtime logs does not prohibit the dedicated, owner-authorized offline probe record. `probe-ledger-v1.schema.json` describes one JSONL record per dispatched attempt, including invalid/refused/timed-out attempts and validation repair. Save sanitized request BODY, exact bounded response bytes where received, official provider request ID, model/profile/rate versions, latency, tokens/reservation/cost status, score hash if validated, and bounded validation errors. Never save Authorization headers, API keys, cookies, participant identifiers, user messages unrelated to the case, or real participant guesses in this ledger. Probe inputs must be creator-authored nonpersonal cases. Null response bytes means none received; do not invent a body. Base64 preserves malformed/non-UTF8 output without treating it as executable.

Store diagnostics in a separate private probe directory, not generic logs/research tables or frontend-served files. Default raw probe retention 7 days; explicit owner export retains the downloaded copy under its declared plan. Capture every attempted sample in case order; a selected gallery is a separate clearly labeled view and cannot replace the ledger. This preserves quality/fidelity analysis without claiming operational logs contain zero raw material when they are intentionally diagnostic. Mock ledgers must say mock_fixture and report zero actual provider calls/cost. These are contracts for future runs; this pack contains no fabricated probe results.


## Exact provider preflight fixtures

The canonical instruction template is director-template-v1.txt, and the provider-supported projection is provider-motion-score-v1.schema.json. Required GenerateContext.repairErrors is null for an initial call, or an array of1–20 closed ScoreError code/path records for validation repair; path≤200 characters. Compile the entire request before reservation. Runtime and probe input-bound ceilings are 32768; runtime output remains 6000, probe output 12000. Price reserve is ceil(B×inputUSDperMillion + outputTokenCap×outputUSDperMillion) microdollars for actual compiled B=UTF8(request)+1024, not the full 32768 when B is smaller. Output is always fully reserved. Existing dollar caps/defaultzero and external approval do not increase. A model whose conservative reserve cannot fit its configured cap is rejected.

contract-fixtures/ contains literal transcriptions of the three specified first scores and nine complete request JSON fixtures: each scene blind,240-codepoint 4-byte-Unicode guess, and that same guess plus 20 maximum-path-length validation errors. The model field is200 literal M characters solely to measure the allowed maximum field size. These are offline request-shape examples, NEVER runnable provider/model IDs or outputs. No requests were sent. provider-preflight-measurements.json records exact compact UTF8 byte counts plus 1024 framing allowance; do not call those measured tokens. Baseline maximal bound 16363 fits 32768. Every generated application request must still pass the same preflight, because later score/template/model edits can be larger.

The input reservation assumes selected-model text tokenization uses at most one token per serialized UTF8 byte and at most 1024 additional framing tokens. Verify this model-specific assumption during configuration and lock dispatch if actual reported usage exceeds the reserved bound. Do not silently truncate context, omit meaning invariants, increase output limits or money ceilings, or treat fixture/model-placeholder strings as activation permission.
